# 우리집 칭찬톡 0.6.7

기록이 쌓인 자녀폰에서 화면 갱신 중 큰 JSON을 메인 스레드에서 반복해서 읽던 문제와, 프로세스 종료 후 메시지 수신만 재개되지 않던 문제를 수정합니다. 미발신 기록을 안전하게 묶고 전송 속도를 제한해 밀린 기록이 한꺼번에 Telegram 요청으로 몰리는 일을 줄입니다.

- 화면 데이터 읽기·해석을 IO 스레드로 옮깁니다. 여러 갱신 요청은 합쳐 처리하고, 화면이 닫히면 화면용 읽기를 중지합니다. 자녀 선택이나 계정이 바뀌면 이전 결과를 적용하지 않습니다.
- 한 번의 화면 읽기에서 가족 명단과 역할을 함께 계산하고, Android 보안 저장소의 토큰 해독도 한 번만 수행합니다. 초기 칭찬판 준비에서도 같은 정보를 반복해서 읽지 않습니다.
- 가족 칭찬판의 중복 확인 ID를 SQLite 인덱스로 옮깁니다. 기존 ID와 승인·잔액·이동 기록을 보존하고, 확인 응답은 해당 메시지 한 건을 조회합니다. 모든 수신자가 확인한 전송 본문은 비우되 중복 방지 식별자와 해시는 보존합니다.
- 상대 앱과 묶음 지원 여부를 확인한 뒤, 같은 상대에게 보낼 가족 대화 또는 위치·칭찬 패킷과 확인 응답을 최대 16개씩 압축해 보냅니다. 실제 한 묶음 크기는 Telegram의 4,096자 제한과 압축 해제 후 64 KiB 제한에 따라 더 작아질 수 있습니다. 각 기록의 ID·시각·권한 검증·개별 확인 상태는 유지합니다.
- 지원 여부를 확인하지 못했거나 상대가 이전 버전이면 기존 형식으로 보냅니다. 묶음 확인이 오지 않으면 원래 개별 형식으로 재시도합니다. 수신 묶음의 저장과 Telegram 수신 커서는 한 트랜잭션으로 처리합니다.
- 같은 상대에게 약 1.1초보다 자주 새 전송 요청을 시작하지 않으며, Telegram이 429와 대기 시간을 돌려주면 지정된 시간 동안 기다립니다. 대기 원인 분석을 위해 요청 종류·오류 코드·대기 초만 진단 로그에 남깁니다. 토큰·좌표·대화 본문은 이 로그에 넣지 않습니다.
- 사용자가 켜 둔 수신 서비스는 시스템의 프로세스 재생성 시 다시 시작하도록 요청합니다. 수신 중지를 선택한 설정은 그대로 존중합니다. 강제 종료나 Android 실행 제한까지 무조건 복구하는 보장은 아닙니다.

버전 코드는 20, 로컬 데이터베이스 버전은 7입니다. 앱을 삭제하거나 가족방을 새로 만들 필요 없이 같은 서명의 APK를 덮어 설치합니다. **실제 묶음 전송에는 보내는 쪽과 받는 쪽 모두 0.6.7 이상이 필요합니다.** 앱에 표시되는 대화는 계속 개별 말풍선입니다. 기존 가족방 참여 인사, 별 아이콘 복구, 기본 무음·단일 메시지 알림, 적응형 메시지 확인 및 이동 중 20초 위치 측정은 유지합니다.

이 업데이트는 별도 중계 서버를 도입하지 않습니다. 상대가 오프라인이면 개별 수신 확인까지 대기가 이어집니다. 부모의 주기적인 전체 칭찬판 동기화 요청은 유지하며, 변경분만 동기화하는 별도 프로토콜은 이번 범위에 포함하지 않습니다. 전송 묶음과 간격 제한은 요청 수와 순간 집중을 줄이지만 Telegram의 모든 제한을 없애지는 않습니다.
