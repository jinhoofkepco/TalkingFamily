# 엄마·아빠·아들·딸의 가족방

0.6.0은 2~8명의 가족 대화방에 자녀별 위치와 공동 칭찬판을 더합니다. 텔레그램 앱의 그룹을 만들 필요는 없습니다. 가족 앱끼리 각 휴대폰의 봇을 통해 메시지를 전달합니다. **참여할 모든 휴대폰을 0.6.0 이상으로 업데이트**합니다. 기존 0.5.0 가족방 코드를 그대로 쓸 수 있습니다.

## 준비와 참여

휴대폰마다 BotFather에서 별도의 봇을 만들고, 모든 봇의 Bot-to-Bot Communication Mode를 켭니다. 기존 아빠·아들의 봇은 그대로 쓰고 엄마·딸에게 새 봇을 마련하면 됩니다. [공식 봇 간 통신 설명](https://core.telegram.org/bots/features#bot-to-bot-communication)

봇 생성과 Bot-to-Bot 설정은 아빠나 엄마 한 사람의 Telegram 계정에서 모두 관리해도 됩니다. 설정은 봇별로 적용되며, 휴대폰마다 BotFather를 열거나 아들↔딸 조합을 따로 등록할 필요는 없습니다. 각 앱에는 서로 다른 본인 봇 토큰을 넣고 같은 가족방 코드로 참여합니다.

한 명이 앱의 **가족방 관리**에서 이름·가족 관계와 각 봇의 `@사용자명`을 입력해 방을 만듭니다. 생성할 때 입력한 봇과 연결 확인 메시지를 주고받습니다. 만든 방의 코드를 복사해 가족에게 전달합니다. 다른 기기는 코드를 붙여 넣어 **가족 명단을 확인한 뒤 참여**를 누릅니다. 봇 토큰은 본인의 휴대폰에만 넣고 공유하지 않습니다.

이미 1:1 연결을 사용하는 기기는 같은 토큰을 재사용합니다. 새 기기는 처음 화면에서 가족방에 바로 참여할 수 있습니다. **엄마·아빠**는 모든 아들·딸의 위치·칭찬판을 확인하고 관리합니다. **아들·딸**은 자신의 위치를 부모에게 공유하고 본인의 칭찬판에서 사용을 요청합니다. **가족** 역할은 대화만 사용합니다. 참여 전에 이름과 역할을 확인하세요.

## 양부모의 위치·칭찬판

부모의 위치·칭찬판 탭 위에서 자녀를 선택합니다. 선택은 두 탭에 함께 적용되며, 지도·시간 막대·날짜별 이동 기록과 스티커 잔액·보상·승인 요청이 자녀별로 분리됩니다. 엄마와 아빠 모두 지급·편집·승인·거절할 수 있습니다.

자녀 휴대폰이 변경 사항을 순서대로 확정해 부모 모두에게 보냅니다. 부모가 동시에 같은 사용 요청을 승인해도 한 번만 차감하고, 늦은 요청에는 이미 처리했다는 결과를 보냅니다. 보상을 동시에 수정하면 먼저 확정된 편집을 유지하고 다른 부모에게 최신 내용을 확인하도록 안내합니다. 자녀가 오프라인이면 마지막으로 확인한 내용을 보여 주고 새 변경은 **처리 결과 대기**로 표시합니다. 최초 동기화 전의 잔액은 0으로 단정해 표시하지 않습니다.

자동 위치 공유가 꺼져 있으면 업데이트나 가족방 참여가 이를 켜지 않습니다. 켜져 있는 경우 명단의 엄마·아빠에게 위치·상태를 전달합니다. 현재 위치 한 번 보내기도 부모에게만 전달합니다. 형제자매·‘가족’ 역할에는 위치와 칭찬 기록을 보내지 않습니다.

기존 자녀 폰의 칭찬 기록을 기준으로 가족 칭찬판을 시작합니다. 기존 부모 폰의 이동 기록은 원래 연결한 자녀에게 연결해 보관합니다. 새 부모는 동기화된 최근 기록과 이후 기록을 받으며, 다른 부모의 전체 과거 위치 보관함을 복사하지 않습니다. 새 가족방에서도 자녀의 마지막 칭찬판을 이어갑니다. 휴대폰의 앱 데이터를 지우면 복원용 서버가 없으므로 해당 기기의 원본 기록이 사라집니다.

## 메시지와 지난 기록

- 가족방의 메시지는 자신을 제외한 명단 전체로 전송합니다. **2/3 전달**은 3대 중 2대의 앱이 메시지를 저장했다는 의미이며 읽음 표시는 아닙니다.
- 상대가 오프라인이면 해당 상대의 전송만 대기합니다. 재전송하거나 앱을 다시 시작해도 같은 메시지를 중복해서 추가하지 않습니다.
- 예전 1:1 대화는 메뉴에서 별도로 열고 보냅니다. 새 가족방으로 복사하지 않습니다.
- 대화가 많으면 이전 기록을 더 불러옵니다. 업데이트 때 기기에 남은 기존 대화를 별도로 보관하므로 앞으로 최근 기록 범위에서 빠져도 유지됩니다. 과거 버전에서 이미 지워진 메시지는 복구하지 못합니다.
- 읽던 위치는 새 메시지가 와도 유지하며 **새 메시지**를 눌러 최신 대화로 이동합니다.

메시지 수신을 켜 두고 인터넷을 연결해야 합니다. Android 절전·강제 종료·재부팅으로 중단되면 앱을 다시 엽니다. Telegram이 미수신 업데이트를 무한 보관하지 않으므로, 발신 휴대폰은 확인을 받기 전까지 로컬 전송 기록을 보관하고 재시도합니다. 발신 기기의 앱 데이터를 지우면 그 기기의 미전달 기록도 사라집니다. [Telegram 업데이트 보관 정책](https://core.telegram.org/bots/api#getting-updates)

### 특정 가족에게만 전달 대기일 때

0.6.2부터 상대 봇 조회 실패, Bot-to-Bot 꺼짐, 전송 권한 거절을 구분해 안내합니다. 0.6.1까지의 ‘상대 봇 이름과 두 봇의 Bot-to-Bot 설정을 확인’ 문구는 모든 400·403 오류에 공통으로 표시되어, 그 문구만으로 설정이 꺼졌다고 판단할 수 없습니다.

텔레그램이 개인 대화를 찾지 못했다고 명확히 거절한 경우, 앱은 명단의 `@사용자명`을 조회하고 실제 봇 ID가 저장된 ID와 같은지 확인한 뒤 같은 메시지를 한 번 더 보냅니다. 대화 내용은 확인되지 않은 사용자명으로 보내지 않습니다. 기존 방과 전달 대기 기록에도 적용되므로 이 보완을 위해 새 방을 만들 필요는 없습니다. 네트워크 응답 유실·요청 제한·Bot-to-Bot 꺼짐은 이 즉시 재시도의 대상이 아닙니다.

이름 조회는 공식 Bot API의 `getChat` 경로를 사용합니다. 숫자 ID로 처음 전송한다고 항상 실패하는 것은 아니므로, 이 보완이 모든 전달 대기의 원인을 해결하는 것은 아닙니다. [Bot API 이름 조회 처리](https://github.com/tdlib/telegram-bot-api/blob/e3e9dd8e5b3d7ab8537cd5a10dc31d5ffa8f82d1/telegram-bot-api/Client.cpp#L7249), [TDLib 사용자 조회](https://github.com/tdlib/td/blob/ea97bcdd3a15523c58ddfe772b4547187cf5bbeb/td/telegram/UserManager.cpp#L5184)

### 메시지가 늦게 도착하거나 늦게 보일 때

0.6.3은 실제 대화 화면과 배경 상태를 구분합니다. 가족방 또는 기존 1:1 대화를 보고 있고 화면이 켜져 있으며 잠겨 있지 않으면 즉시 수신을 시작하고 긴 수신 요청으로 새 메시지를 기다립니다. 메시지가 생기면 그 요청이 응답하므로 최대 대기 시간까지 일부러 기다리지 않습니다.

대화 화면을 닫거나 설정·지도·칭찬판으로 이동하면 다음 확인은 5초 뒤입니다. 새 대화가 없으면 다음 간격을 10→20→30→60초로 늘리고 이후 60초를 유지합니다. 일반 배경 실행은 60초 간격에서 시작합니다. 어느 단계에서든 새 대화를 저장하면 그 시각부터 다음 확인을 5초 뒤로 잡습니다. 연속해서 받으면 5초를 유지하고, 다시 없으면 간격을 늘립니다. ACK·위치·칭찬 상태·중복 대화는 새 메시지로 세지 않습니다.

배경 확인은 실제 간격을 두므로 조용할 때의 첫 메시지는 다음 확인까지 최대 약 60초 지연될 수 있습니다. 받는 기기의 확인 주기는 전달 수와 위치·칭찬 기록이 보이는 시점에도 적용됩니다. 메시지 수신을 꺼 두었거나 Android 절전·강제 종료·네트워크 장애가 있으면 이 간격대로 실행되지 않을 수 있습니다.

보낼 메시지를 로컬에 저장하면 수신 대기를 깨워 송신합니다. 위치 전송 등 일반 송신은 배경 수신 시각을 앞으로 당기거나 빠른 대화 주기를 계속 유지시키지 않습니다. 메시지 전송 요청 자체는 중단하지 않으며, 텔레그램이 지정한 재시도 대기는 계속 지킵니다. 같은 봇의 업데이트 수신과 저장 위치(offset)는 휴대폰 안에서 한 곳이 관리합니다.

받는 앱은 메시지와 수신 위치를 함께 저장한 직후 화면 갱신 신호를 보냅니다. 화면은 나머지 수신 확인 전송이나 네트워크 대기가 끝나기 전에 저장된 대화를 표시하며, 이전 페이지를 많이 펼쳐도 최신 페이지를 먼저 표시합니다. 수신 서비스가 실행 중이면 화면의 5초 상태 갱신은 별도 네트워크 조회를 하지 않습니다. 보내는 앱과 받는 앱 모두 업데이트해야 양쪽 개선이 적용됩니다. Firebase나 클라우드 중계는 사용하지 않습니다.

## 명단 변경과 나가기

처음 만든 명단은 방 ID에 고정됩니다. 가족을 추가·제외하려면 새 방을 만들고 새 코드를 참여할 가족 모두에게 전달합니다. 이전 방에서 나가도 다른 가족에게 알림을 보내거나 그 기기의 기록을 지우지 않습니다. 이전 방은 송수신을 멈추며 같은 코드로 다시 들어가면 저장된 기록과 대기 메시지를 이어갑니다.

기존 1:1 연결은 별도로 유지됩니다. 가족방에서 나가면 그 방의 위치·칭찬 동기화도 멈춥니다. 기존 자녀 1:1 연결이 없는 기기에서는 자동 공유도 중지합니다. 가족 연결을 전체 초기화하면 이 휴대폰의 방·대화·위치·칭찬 기록이 지워집니다.

가족방 코드는 비밀번호가 아니며 토큰을 포함하지 않습니다. 가족 이름과 봇 명단을 담으므로 필요한 가족에게만 전달하세요. 수신 앱은 방 ID와 고정한 봇 ID를 확인합니다. 봇 통신은 Telegram 비밀대화의 종단간 암호화를 제공하지 않습니다.
